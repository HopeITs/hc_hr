# تقرير الأعمال الحالية — موديول التوظيف

التاريخ: 17 أيلول 2026. يغطي هذا التقرير الأعمال المنفذة في جلسة تطوير واجهات الطلبات وتصحيح الصلاحيات ومعالجة مشكلة التشغيل المحلية. لا يعني اكتمال دورة التوظيف كاملة.

## 1. حالة المهمتين

| المهمة | الحالة الفعلية |
|---|---|
| بداية واجهات Request / Create / Details | منفذة: قائمة الطلبات، إنشاء طلب عادي وحفظه مسودة، وعرض التفاصيل |
| Draft / Edit / Submit + Versioning + Duplicate Submit Protection | منفذ منها حفظ المسودة الأولية فقط؛ التعديل والإرسال وإنشاء النسخ ومنع تكرار الإرسال لم تنفذ بعد |
| Direct Opening للـ HR | قواعد الصلاحيات موجودة؛ واجهة الإنشاء وخدمته لم تنفذا ضمن هذا العمل |

## 2. الواجهات المنفذة

- **قائمة الطلبات:** عرض الطلبات المسموح للمستخدم برؤيتها، بحث برقم الطلب، ترتيب، ورابط إلى التفاصيل. ليست قائمة غير مقيدة بكل طلبات المؤسسة؛ المسودات خاصة بصاحبها.
- **إنشاء طلب عادي:** حقول تتغير بحسب نوع الطلب: ملء شاغر، زيادة الملاك، تخفيض الملاك، إنشاء منصب، إغلاق منصب، إغلاق شاغر.
- **حفظ مسودة:** توليد رقم الطلب، تثبيت صاحبه وحالته ومساره على الخادم، حفظ البيانات الأولية وتسجيل حدث الإنشاء. لا ينشئ الحفظ منصباً فعلياً أو شاغراً أو نسخة مرسلة.
- **التفاصيل:** ملخص الطلب وبيانات المسودة، وعرض النسخ الموجودة وبعض تفاصيل النسخة المختارة، والأحداث والتعليقات والتأكيدات الخارجية عند وجودها. عرض هذه البيانات لا يعني تنفيذ أفعال إضافتها أو مسار الموافقات.
- **التكامل:** روابط ضمن المسارات الحالية المحمية وبادئة اللغة، مدخل في القائمة الجانبية، وترجمة عربية وإنكليزية مع دعم RTL.

## 3. القرارات والصلاحيات المطبقة

### نطاق إنشاء الطلب — D49

اعتماد الهيكل الإداري عبر `direct_manager_id`، مع مفهوم موحد `manageablePositionIds` للقوائم والتحقق عند الحفظ:

- المنصب القائم المستهدف يجب أن يكون من مرؤوسي المدير بأي عمق، دون منصب المدير نفسه.
- الأب المقترح في CreatePosition يمكن أن يكون منصب المدير نفسه أو أي منصب ضمن شجرته.
- المدير المؤهل الذي لا يملك مرؤوسين يستطيع طلب إنشاء منصب تحت منصبه مباشرة.
- اختلاف المحافظة أو البرنامج لا يمنع العملية متى كانت العلاقة الإدارية صحيحة، ولا يمنح صلاحية على شجرة أخرى.
- التحقق من الحقول التنظيمية يتبع قواعد المشروع الموجودة، ومنها توافق المركز والمحافظة وفق PositionForm.
- نطاق الرؤية D30 منفصل عن نطاق الإنشاء؛ لم يتحول تلقائياً إلى رؤية كل الأعماق.

### مسار HR — D50

- منع HR من إنشاء Normal Request حتى لو كانت درجته 1 أو 3 أو 5.
- مساره المعتمد هو Direct Opening فقط، مع إبقاء قواعد صلاحيات هذا المسار.
- فصل أهلية الدرجة عن صلاحية الدور، وتحديث صياغة D33 والوثائق المرتبطة.
- تطبيق القيود على الخادم، وليس بإخفاء الزر فقط؛ كما تمنع Policy تعديل أو إرسال الطلب العادي عند استخدام دور HR.

### حماية الوصول والبيانات

- القوائم والتفاصيل تمر عبر نطاق الرؤية وPolicy.
- يعاد فحص نطاق الطلب عند تحديث شاشة التفاصيل، وتقتصر النسخة المختارة على نسخ الطلب نفسه.
- يعاد فحص تبعية المنصب المستهدف أو الأب عند حفظ المسودة.
- حقول المالك والحالة والمسار لا تؤخذ من بيانات قابلة للتلاعب من المتصفح.

## 4. معالجة مشكلة التشغيل المحلية

في الفحص الأول كانت `hr_db` بلا حسابات أو موظفين. في الفحص اللاحق بعد إرسال خطأ صفحة الطلبات، أصبحت تحتوي على 257 مستخدماً و270 موظفاً و165 منصباً؛ لم ننفذ عملية استعادة هذه البيانات ضمن المعالجة المسجلة.

الخطأ اللاحق كان غياب جدول `hchr_recruitment_requests`، لأن تحديثات التوظيف لم تكن مطبقة على القاعدة الحالية. تم:

1. مراجعة حالة migrations والتأكد من غياب جداول التوظيف.
2. تطبيق ملفات التوظيف الثمانية الموجودة بتاريخ 15 و16 أيلول، بما فيها تحديثات الصلاحيات، على `hr_db`.
3. التحقق من نجاح استعلام الطلبات وتصْيير مكوّن صفحة الطلبات على الخادم للحساب الوارد في الخطأ.
4. التحقق من بقاء أعداد المستخدمين والموظفين والمناصب كما كانت قبل التطبيق.

لم يُستخدم `migrate:fresh` ولم تُعدّل كلمات المرور. الحساب الوارد في الخطأ يحمل دور `HR-SYR` فقط؛ لذلك غياب زر إنشاء الطلب العادي متوافق مع القرار المعتمد. لا توجد بعد واجهة فتح مباشر يمكن لهذا الحساب استخدامها.

## 5. التحقق المنجز

هذه نتائج التحقق المسجلة أثناء التنفيذ، وليست إعادة تشغيل للاختبارات عند كتابة هذا التقرير:

| التحقق | النتيجة |
|---|---|
| اختبارات التوظيف | نجاح 39 اختباراً و372 تأكيداً |
| تنسيق PHP باستخدام Pint | ناجح |
| بناء الواجهة باستخدام npm run build | ناجح، مع تنبيهات عن حل مسارات الخطوط وقت التشغيل |
| تجربة المتصفح بقاعدة SQLite تجريبية منفصلة | إنشاء مسودة وعرض تفاصيلها، ومنع HR من صفحة الإنشاء برمز 403 |
| العرض | فحص سطح المكتب والعربية RTL على الموبايل دون تجاوز أفقي |
| معالجة قاعدة MySQL المحلية | نجاح تحديثات التوظيف وتصْيير مكوّن قائمة الطلبات على الخادم |

تغطي اختبارات الصلاحيات المدير الوطني ومرؤوسيه في محافظة أخرى، العمق المتعدد، منع الوصول إلى شجرة مدير آخر، إنشاء منصب تحت مدير بلا مرؤوسين، رفض الأب خارج الشجرة، اختلاف البرنامج والمحافظة، ومنع HR بدرجات 1 و3 و5.

الاختبار العام `LivewireMutationCoverageTest` يكشف ثلاثة نواقص سابقة خارج التوظيف في تصنيف إجراءات `toggleVacancies` و`updatedFormCityId` لمكونات المناصب. لم تُصلح ضمن هذه المهمة؛ لذلك لا يصح اعتبار جميع اختبارات المشروع ناجحة.

## 6. الملفات الرئيسية

- `app/Livewire/Recruitment/Requests/`: مكونات القائمة والجدول والإنشاء والتفاصيل.
- `app/Services/RecruitmentRequestDraftService.php`: حفظ المسودة الأولية.
- `app/Services/RecruitmentScopeResolver.php`: نطاق الهيكل الإداري وأهلية الطلب.
- `app/Policies/RecruitmentRequestPolicy.php`: تفويض عمليات الطلب.
- `routes/recruitment.php` و`routes/web.php`: تسجيل المسارات.
- `resources/views/livewire/recruitment/requests/`: قوالب الواجهات وأجزاء الحقول.
- `resources/lang/ar/recruitment.php` و`resources/lang/en/recruitment.php`: الترجمة.
- `config/access-control.php` و`config/recruitment.php`: إعدادات الصلاحيات والقواعد.
- `tests/Feature/Recruitment/RecruitmentCreationScopeTest.php` و`RecruitmentRequestScreensTest.php`: اختبارات النطاق والواجهات.
- وثائق القرارات والأنواع والصلاحيات ونسخ المشاركة، و`تقرير.md`: تحديث القرارين وحالة التنفيذ.

## 7. العمل المتبقي

1. تعديل المسودة الموجودة واسترجاع بياناتها في نموذج التعديل.
2. التحقق النهائي عند الإرسال وتنفيذ Submit وإعادة الإرسال حسب القواعد.
3. إنشاء نسخ ثابتة للطلب عند الإرسال وربطها بالدورة المعتمدة.
4. منع تكرار الإرسال، بما يشمل الطلبات المتزامنة وإعادة المحاولة.
5. إنشاء وتشغيل Workflow ومعالجة انتقالات الحالة والموافقات.
6. بناء واجهة وخدمة Direct Opening للـ HR.
7. استكمال اختبارات هذه العمليات عند تنفيذها، وحسم أي قرار غير محسوم بالرجوع للوثائق وصاحب المشروع.

التعديلات الحالية موجودة محلياً وغير محفوظة في commit بحسب فحص Git عند إعداد التقرير؛ لم يُنفذ نشر لهذه التعديلات ضمن هذه الجلسة.
