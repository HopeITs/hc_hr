## 2. ما هو غير مفهوم

- **أعمال HR مخفية.** القائمة الجانبية مطويّة افتراضيًا وتعرض «مساحتي» فقط. الموظفون والعقود والحضور والتقارير موجودة تحت قائمة منسدلة اسمها «التصنيفات» في لوحة التحكم. موظف HR جديد لن يجدها. ← افتح القائمة على الشاشات ≥1280، أو اعرض أيقونة لكل قسم في الشريط.
- **أسماء الأدوار بالإنجليزية الخام** (`HR-ALP`, `super-admin`, `employee`) في صفحة الصلاحيات وأي مكان تظهر فيه. ← تسميات مترجمة: «موارد بشرية – حلب»، «مدير النظام»…
- **مصطلحات متضاربة:** المنصب / الوظيفة / المسمى الوظيفي؛ المدينة / المحافظة / مكان الإقامة؛ «موظف» في القائمة و«متطوع جديد» في نموذج الإضافة. ← معجم واحد في `lang/ar`.
- **عمودان باسم «النوع»** في جدول إجازاتي («نوع الإجازة» و«النوع» = يوم/ساعة). ← «بالأيام/بالساعات» أو دمجهما في عمود المدة.
- **أرصدة بالدقائق:** «8 أيام وساعتان و40 دقيقة» و«6 أيام و48 دقيقة». ← تقريب لأقرب نصف يوم في العرض، والدقة في التفاصيل.
- **«المتاح الآن 14 / الكلي 43»** بلا شرح لماذا المتاح أقل (الاستحقاق بالأثلاث). ← سطر «يُستحق الباقي على مراحل: التالي في …».
- **عبارات تقنية للمستخدم:** «كل بند يمرّ بنفس التحقق الذي تمرّ به صفحته»، «أخرج … من المتصفح»، «HC-HR والبصمات من التقرير المرفوع». ← صياغة مستخدم.
- **أسماء البرامج بالإنجليزية** في صفحات عربية («Leadership Empowerment & Achievement Program»). ← ملء `name_ar`، والاحتياط بالعربية.
- **منتقي الشهر والتاريخ يعرضان «November 2026»** وأرقامًا لاتينية بتنسيق المتصفح. ← مكتبة تاريخ تدعم العربية (Flatpickr مع locale `ar`).
- **«1 أشخاص»** ← استخدام `trans_choice` (شخص واحد / شخصان / أشخاص).

## 3. ما هو معقّد

- **لوحة التحكم للموظف** تبدأ بأزرار «تخطيطي / التصنيفات / تعديل / إعادة الضبط». أدوات كل مربع أربعة (تثبيت، تصغير، تكبير، إخراج). والطقس والساعة يأخذان أفضل مكان، بينما «يحتاج انتباهك» تحته. ← للموظف: إخفاء التخصيص خلف زر واحد «تخصيص»، ووضع «يحتاج انتباهك» ورصيد الإجازة أولاً.
- **جدول إجازاتي:** بحث عام، اختيار أعمدة، تحديث، عدد الصفوف… لأربعة طلبات. ← بطاقات بسيطة للموظف (قائمة زمنية)، والجدول الكامل لـ HR فقط.
- **قرار المدير بخطوتين:** اختيار «قبول» ثم «حفظ القرار»، وحالة الاختيار بالكاد تُرى. ← زر «قبول» ينفّذ مباشرة مع «تراجع» في الإشعار، و«رفض» يفتح خانة السبب.
- **تأكيد مزدوج للإجازة:** الملخص في الخطوة 5 ثم نافذة تأكيد تكرّره. ← الاكتفاء بالملخص.
- **الموظف البديل:** قائمة أصلية فيها ~80 اسمًا مع تكرار (ريتا شامي ×2، طارق صباغ ×2) بلا ما يميّزها. ← قائمة بحث (Tom Select / `flux:select searchable`) مع المنصب تحت الاسم.
- **إضافة موظف:** 8 حقول أسماء إلزامية (عربي + إنجليزي)، فقرة تعليمات طويلة، و«اسم المستخدم» مطلوب لكنه ليس في التبويب الظاهر، وتبويبات تبدو فعّالة وهي مقفلة حتى الحفظ. ← الإنجليزي اختياري مع نقل حرفي مقترح، وإظهار اسم المستخدم في القسم الأول، وتعطيل التبويبات بصريًا مع سبب.
- **جدولي الشهري للموظف** يعرض «الأشخاص: 1» وتجميعًا حسب المدينة والبرنامج. ← للموظف: تقويم شهري بسيط بلا تجميع ولا عداد أشخاص.
- **العقد الجديد:** «اختر المدينة أولًا» والمدينة مثبتة أصلًا؛ «المناصب» بصيغة الجمع لاختيار واحد؛ «النوع» ← «نوع الدوام».

## 4. التسلسل المريح المقترح

1. **الموظف — طلب إجازة:** زر «طلب إجازة» نصّي دائمًا (على سطح المكتب يظهر «+» فقط حتى المرور عليه) ← النوع ← يوم/ساعات ← التواريخ (مع منع الماضي وإظهار قاعدة كانون فورًا) ← سبب اختياري قصير + بديل ببحث ← إرسال بلا نافذة ثانية.
2. **المدير — الموافقة:** إشعار ← بطاقة الطلب مع رصيد الموظف ومن غائب في الفريق بنفس الأيام ← قبول بنقرة / رفض بسبب.
3. **HR — موظف جديد:** الاسم العربي + الرقم الوطني + المدينة ← حفظ مسودة تلقائي ← «إنشاء عقد له الآن؟» مباشرة بعد الحفظ (الموظف معبّأ مسبقًا).
4. **HR — الحضور:** رفع ← قائمة «أيام تحتاج قرارك» (الماضية فقط) ← قرار جماعي للأيام المتشابهة ← قفل.

## 5. أشياء جيدة تُحفظ

- الملخص الحي في نموذج الإجازة (أثر الطلب على الرصيد) ونموذج العقد (اللوحة الجانبية).
- رسالة التداخل مع إجازة مقبولة واضحة وتقترح الحل.
- «إجازتك ما زالت بانتظار القرار — مرّ يومها الأول» في «يحتاج انتباهك».
- الموبايل: لا تمرير أفقي، شريط سفلي، والزر «طلب إجازة» بنص كامل.
- رسالة بعد الإرسال تقول من سيقرّر وما الخطوة التالية.
