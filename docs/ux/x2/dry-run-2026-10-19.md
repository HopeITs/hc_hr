Part of [usability-baseline.md](../usability-baseline.md). Task X2 (R-15).

## 3. Defects found in the instrument, and their fixes

| # | Where | Defect | Fix |
|---|---|---|---|
| 1 | Scripts, Task A path | Named a "Holidays and Leaves" menu. That is only the breadcrumb; the menu is the *Time & Leave* section → *My Leaves*. | Scripts v1.1 |
| 2 | Scripts, Task D card | "One-year annual contract ending [date], N days a week, H hours a day" does not match the composer: contract types are *Volunteer Contract* / *Specific Voluntary Service Contract* (to 31 Dec) / *Trial Volunteer Contract* (3 months); there are *Type* and *Location* fields; the end date is pre-filled; the schedule is a day range plus hours. A participant could not have followed the old card literally. | Scripts v1.1: new EN/AR card, 6-item end-state check |
| 3 | Scripts, Task B path | Missed the second search box (the *Name* column's own) and the dashboard *Contact The Team* search, which can also reach a profile. | Scripts v1.1: both accepted |
| 4 | Session data, Task B | The ALP target (ID 4) was on the first page of the default list, so it could be read off without searching. | `session-states.php`: the target may not be on the first two pages; rebuilt (ALP target now ID 40) |
| 5 | Session data, Task C | Both city managers landed on the same head-office position, so each saw the other city's pending requests (7 in scope each). | `session-states.php`: each city's manager must hold a different position; rebuilt (ALP 4 / HMS 5 pending in scope, own city only) |
| 6 | Session data, bells | X1 spreads leave notifications at random, so the staff and manager personas' bells held decision links to requests they cannot open (an employee cannot open `/leaves/all`). | `session-states.php`: staff bells emptied; each manager gets only the notices for its 3 requests |
| 7 | Session procedure | A first-visit product tour covers the page (dashboard "Step 1 of 15"; again "Step 1 of 16" for the manager in the same browser). It is stored per tour in local storage. It would interrupt timed tasks. | Scripts v1.1 §0.1: the moderator skips every tour per persona before the participant arrives |

## 5. Things the executor noticed on the way (for the named consumers; **not** user findings)

Each item was seen in the DOM or on screen during the walkthrough. Whether it troubles users is for the sessions to show. None was changed.

| What was seen | Where | Consumer |
|---|---|---|
| The leave modal's *Cancel* is a link to `/leaves` (confirmed in the live DOM), and background page controls stay in the accessibility tree while the modal is open. | Task A modal | A5-M, A5 |
| Radio buttons are exposed by their values: the contract-type cards as "1", "5", "3", schedule mode as "1"/"2". The *From day* / *To day* lists are named only "Select". | Composer | A5 (AC-A5-02/03) |
| The Arabic printed-wording preview keeps "9:00 AM … 5:00 PM" in Latin form. | Composer, Schedule | A4 |
| The sidebar's "Time & Leave" / "الإجازات" heading is an inline EN/AR ternary in `sidebar.blade.php`, not a translation key. | Sidebar | A4 |
| At 1024 px wide (sidebar open), the contract-type cards and the *Positions* list truncate their text ("Acco… Hope C… Full"). It was readable at 1440×900. | Composer | M1 / B4-D (desktop sizes 1280/1440 are the SHARED RULES set; 1024 is not) |
| The leave success toast says only "Operation completed successfully": no status, no next actor. | Task A | A3 (AC-A3-03), B0 |
| The composer saved the new contract with auto-renew **on**; the walkthrough did not see a question about it. | Task D | A6 (draft/auto-renew status) |
| The X1 position copies carry number suffixes ("Deputy Chief Executive Officer 113"), so several near-identical positions appear. This comes from the synthetic data, not the app; scenario cards must name the position exactly as listed. | Composer | X2 (card filling) |
